You are landing **one** PR authored by Victor. Rebase it onto `main`, resolve only the conflict classes listed below, then arm GitHub's native auto-merge queue and stop.

Usage: `/land-pr` (current branch's PR) or `/land-pr <PR#>`.

**You never merge.** The final step is `gh pr merge --auto --squash`, which only *arms* the queue — GitHub performs the squash merge later, on its own, once required checks pass. Running `gh pr merge` without `--auto` is forbidden here, same as everywhere else in this repo.

## Guards — check all before touching anything

Abort with a one-line reason if any fails:

1. **Not a Dependabot PR.** `gh pr view <PR> --json author --jq .author.login` must NOT be `app/dependabot`. Dependabot PRs belong to `/garden` — pushing to them permanently breaks `@dependabot rebase`.
2. **Authored by Victor.** Never land someone else's branch.
3. **Not a draft.** `gh pr view <PR> --json isDraft`.
4. **Base is `main`, head is not `main`.** Never rebase or force-push `main`.
5. **No unrelated local changes.** `git status --porcelain` on the worktree must be clean before starting.

## Steps

1. **Resolve the PR.** No argument → `gh pr view --json number,headRefName,baseRefName,mergeable,mergeStateStatus`. Argument → same for that number.

2. **Check whether a rebase is even needed.** `main` has `strict: false` branch protection, so GitHub does **not** require the branch to be current. If `mergeable` is `MERGEABLE` and the PR is not conflicted, skip to step 6 — do not rebase for cosmetic freshness. Rebase only when `mergeable` is `CONFLICTING`, or when Victor explicitly asked for fresh CI against current `main`.

3. **Rebase in a worktree**, never in the working tree:
   ```
   git fetch origin main
   git worktree add ../.land-pr-<branch> <branch>
   cd ../.land-pr-<branch> && git rebase origin/main
   ```

4. **Triage every conflicted file** (`git diff --name-only --diff-filter=U`).

   Orientation matters and is easy to get backwards — during a **rebase**, `--ours` is `origin/main` (the upstream you are replaying onto) and `--theirs` is the commit from Victor's branch. This is inverted relative to a merge.

   | Conflicted path | Resolution |
   |---|---|
   | `.github/badges/coverage.svg` | `git checkout --ours` — derived artifact, regenerated by `make coverage` |
   | `*/poetry.lock` | Only if the sibling `pyproject.toml` is **not** conflicted: `git checkout --ours <lock>`, then `cd <service> && poetry lock`, then `git add` |
   | `frontend/yarn.lock` | Only if `frontend/package.json` is **not** conflicted: `git checkout --ours`, then `cd frontend && yarn install`, then `git add` |
   | `CHANGELOG.md`, inside `[Unreleased]` only | Keep **both** sides, main's entries first, drop exact duplicates. Preserve the `### Added` / `### Fixed` / `### Changed` grouping |

   **Everything else is a hard stop.** Any conflict in a source file (`*.py`, `*.ts`, `*.tsx`, `*.sql`), in a manifest (`pyproject.toml`, `package.json`), in a migration, in CI config, or anywhere in `CHANGELOG.md` outside `[Unreleased]`:
   ```
   git rebase --abort
   ```
   then remove the worktree and report the conflicted file list. Do not attempt a resolution, do not guess at intent, do not resolve "the easy ones" and stop on the rest — a partial rebase is worse than none. Victor resolves these.

5. **Verify, then push.** After `git rebase --continue` completes:
   - If any lockfile was regenerated, run that service's tests (`make test-<service>`) — a regenerated lock can pull a new transitive version.
   - `git push --force-with-lease` (never bare `--force`). If it is rejected because the remote moved, stop and report — someone else pushed and you must not clobber it.
   - Remove the worktree: `git worktree remove ../.land-pr-<branch>`.

6. **Arm auto-merge.** Required checks on `main` are `lint`, `test`, `security`, `build`.
   - If any required check is already **failed**, do not arm. Report which one and stop — a red PR is `/garden`'s problem or Victor's, not this command's.
   - If checks are green or pending: `gh pr merge --auto --squash <PR>`.
   - The repo has `delete_branch_on_merge: true`, so the branch is cleaned up automatically.

7. **Report** in this shape:
   ```
   PR #<n> — <title>
   Rebase:      <skipped (already mergeable) | clean | resolved: file, file>
   Tests:       <n/a | make test-<service> passed>
   Auto-merge:  <armed | NOT armed — reason>
   ```

## Hard stops — never do these

- Never `gh pr merge` without `--auto`
- Never force-push `main`, or any branch you did not just rebase
- Never bare `--force` — always `--force-with-lease`
- Never touch a Dependabot PR
- Never resolve a source, manifest, or migration conflict
- Never arm auto-merge on a PR with a failing required check
