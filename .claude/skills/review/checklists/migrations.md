# Migrations checklist

Applies when the diff touches `core/db/` or `core/alembic/`. Risky lane — see `rules/migrations.md`.

- **MIG-1** The migration file was generated by `make revision` (autogenerate header, revision id chain intact). Hand edits only for what autogenerate can't express (rename, data migration, `CONCURRENTLY` index), each recorded in the Decisions.
- **MIG-2** The generated operations match the model change — model is the source of truth. Check constraint names and `server_default`, which autogenerate gets subtly wrong.
- **MIG-3** Risky changes use two steps: NOT NULL on an existing column (nullable → backfill → NOT NULL), large-table index (`postgresql_concurrently=True`), rename (`RENAME COLUMN`, not drop + add).
- **MIG-4** Lock risk on a table above ~10k rows is flagged in the PR Decisions.
- **MIG-5** Schema and data changes are separate migrations.
